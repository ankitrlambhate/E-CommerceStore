# Deployment Guide: E-Commerce microservices on AWS with Docker + Terraform

Deploys the 4 Node.js backends (user, product, cart, order) and the React frontend as Docker
containers on one Ubuntu 22.04 EC2 instance, provisioned entirely by Terraform.

## Architecture

```
Internet ──:80──► [ EC2 (Ubuntu 22.04, public subnet) ]
                    ┌──────────── Docker network "ecommerce-net" ────────────┐
                    │ frontend (nginx, :80)                                  │
                    │   /            -> React app                            │
                    │   /healthz     -> "Frontend is Live"                   │
                    │   /svc/user/*    -> user-service:3001   ─┐             │
                    │   /svc/product/* -> product-service:3002 │ MongoDB     │
                    │   /svc/cart/*    -> cart-service:3003    ├─► mongo:27017
                    │   /svc/order/*   -> order-service:3004  ─┘             │
                    └─────────────────────────────────────────────────────────┘
```

| Component | Image (Docker Hub) | Port |
|---|---|---|
| Frontend (React + nginx) | `<user>/ecommerce-frontend` | 80 (public) |
| User service | `<user>/ecommerce-user-service` | 3001 |
| Product service | `<user>/ecommerce-product-service` | 3002 |
| Cart service | `<user>/ecommerce-cart-service` | 3003 |
| Order service | `<user>/ecommerce-order-service` | 3004 |
| MongoDB (official `mongo:6`) | `mongo:6` | 27017 (container network only) |

Design choices
- **Nginx reverse proxy in the frontend image.** The React app is built with relative API URLs
  (`/svc/user`, ...), so the same image works on any IP/DNS and only port 80 is public.
- **MongoDB runs as a container on the same host**, because every backend needs a database to be useful.
  Its data lives in a Docker volume. (For production use a managed DB such as DocumentDB/Atlas.)
- **Single EC2 instance** keeps the stack simple and fast to apply. The backends talk to each other by
  container name over the Docker network.
- `JWT_SECRET` is generated by Terraform (`random_password`) and passed to the user service.

## Terraform resources

| File | What it creates |
|---|---|
| `terraform/main.tf` | VPC, internet gateway, public subnet, route table + association, security group + rules, Ubuntu 22.04 AMI lookup, `random_password`, EC2 instance |
| `terraform/user_data.sh.tpl` | Boot script: installs Docker, pulls the 5 images + mongo, creates network, runs all containers, self-checks |
| `terraform/variables.tf` | `dockerhub_username` (required), region, tag, instance type, optional `key_name`, `ssh_cidr` |
| `terraform/outputs.tf` | `public_ip`, `public_dns`, `frontend_url`, `verification_urls` |

Security group `ecommerce-sg`

| Direction | Port | Source | Purpose |
|---|---|---|---|
| Inbound | 80/tcp | 0.0.0.0/0 | Public HTTP to the frontend |
| Inbound | 22/tcp | `ssh_cidr` | SSH (set to your IP) |
| Inbound | 3001-3004/tcp | the security group itself | Service-to-service traffic; not reachable from the internet |
| Outbound | all | 0.0.0.0/0 | apt, Docker Hub |

## Prerequisites

- Docker, Terraform >= 1.3, AWS CLI configured (`aws configure`) with permission to create VPC/EC2 resources
- A Docker Hub account (repositories must be public so EC2 can pull without credentials)

## Step 1: Build, test and push the images

```bash
export DOCKERHUB_USER=your-dockerhub-username

# build all 5 images, tag them and push to Docker Hub (prompts for docker login)
./scripts/build-and-push.sh

# optional: run the whole stack locally and smoke-test it
./scripts/test-local.sh          # frontend at http://localhost:8080
./scripts/test-local.sh down     # clean up
```

Each backend returns a sample response on `GET /` (for example `User Service Running`), and also exposes
`GET /health`. The frontend returns `Frontend is Live` on `/healthz`.

## Step 2: Provision and deploy

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # set dockerhub_username (and optionally key_name, ssh_cidr)
terraform init
terraform apply
```

Terraform prints the outputs, for example:

```
frontend_url = "http://<public-ip>"
public_ip    = "<public-ip>"
public_dns   = "ec2-....compute.amazonaws.com"
```

Allow **2-4 minutes** after `apply` finishes for the user-data script to install Docker and pull the images.

## Step 3: Verify

```bash
IP=$(terraform output -raw public_ip)

curl http://$IP/healthz            # Frontend is Live
curl http://$IP/svc/user/          # User Service Running
curl http://$IP/svc/product/       # Product Service Running
curl http://$IP/svc/cart/          # Cart Service Running
curl http://$IP/svc/order/         # Order Service Running
curl http://$IP/svc/product/api/products   # real API call through the proxy
```

Open `http://<public-ip>` in a browser for the storefront homepage.

If you set a key pair, SSH in to inspect the deployment:

```bash
ssh -i <key>.pem ubuntu@$IP
sudo cat /var/log/deploy-status.txt   # summary written by the boot script
sudo tail -f /var/log/user-data.log   # full boot log
sudo docker ps                        # 6 containers: mongo + 5 services
sudo docker logs user-service
```

## Teardown

```bash
terraform destroy
```

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Site not reachable right after apply | user-data is still running; wait a few minutes and check `/var/log/user-data.log` |
| `pull access denied` in the log | Image not pushed, wrong `dockerhub_username`/`image_tag`, or repo is private |
| `exec format error` | Images built on ARM; rebuild with the provided script (it forces `linux/amd64`) |
| `/svc/...` returns 502 | Backend container not running; `docker ps -a` and `docker logs <name>` |
| Changed image or tag | `terraform apply` again; `user_data_replace_on_change` replaces the instance (new public IP) |

## Notes and assumptions

- Default region is `ap-south-1` (Mumbai); change with `aws_region`.
- Default instance type is `t3.small` (2 GB RAM) so MongoDB and 4 Node services fit comfortably.
- `ssh_cidr` defaults to `0.0.0.0/0` for easy testing; restrict it to your own IP.
- Source changes made to the app: a `GET /` sample-response route in each backend `server.js`; everything else is new files (Dockerfiles, `.dockerignore`, `frontend/nginx.conf`, `terraform/`, `scripts/`).
